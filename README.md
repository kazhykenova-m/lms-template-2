# LMS — шаблон на основе ver-29-10

Эта версия создана из актуальных файлов Factum LMS в `ver-29-10`, а не из упрощённой платформы SQLite. Исходная рабочая LMS не изменяется. Предыдущая упрощённая версия сохранена рядом в `lms-template-simple` и в этот дистрибутив не входит.

## Что сохранено

- Админка: пользователи, обучения (бывшие уровни), тесты, практические задания, результаты и достижения.
- Вопросы с одним или несколькими правильными ответами, открытые ответы и собственный вариант ответа.
- Случайная выдача вопросов с квотой на каждый тест; одно случайное практическое задание из обучения.
- Одна попытка, серверный таймер, сохранение черновиков, восстановление черновиков при повторном открытии активной попытки.
- Ручная проверка открытых ответов и практических заданий, публикация проверенных результатов.
- Диаграммы и детализация результатов из исходной LMS.
- Достижения с emoji/SVG-иконками и настройкой условия по обучению.
- Загрузка вложений в ответы и аватар пользователя.

## Что изменено

- Убраны разделы онбординга, стандартов, коинов и обсуждений. Начисление коинов и внешняя интеграция магазина отключены.
- Два типа доступа: администратор и пользователь. Руководителей и самостоятельного назначения полномочий нет.
- Отделы и должности отсутствуют в пользовательских настройках. Две служебные записи `departments=1` и `roles=1` оставлены только для совместимости исходного механизма попыток. Не удаляйте их из базы. Все записи создаются в этой единой области; права зависят от `is_admin`.
- Универсальный светлый интерфейс, адаптивные формы, нейтральный логотип. Настраиваются название, логотип, акцентный цвет, фон, тексты входа, названия разделов и email поддержки.
- Импорт обучения с тестами, вопросами и заданиями через один JSON. Импорт пользователей через CSV, с откатом всех изменений при ошибке.
- Защита от повторной записи одного ответа на задание при потере ответа сервера. Редактируемые достижения не перезаписываются автоматической синхронизацией.
- Нет производственных файлов, журналов, аккаунтов и настроек подключения Factum.

## Установка новой копии

Нужны PHP 8.1+, MySQL 8 или совместимая MariaDB, расширения `pdo_mysql`, `mbstring`, `fileinfo`, `dom`, `session`. Веб-каталог должен указывать на корень этой папки. Абсолютные пути вида `/api/...` предполагают отдельный домен или поддомен, а не установку в подпапку.

1. Создайте **новую пустую базу**, выбрав `utf8mb4`. Не импортируйте эту схему поверх рабочей LMS.
2. Импортируйте `db/schema.sql` в выбранную базу. Схема не создаёт отдельную базу и не содержит тестовых пользователей.
3. Скопируйте `config.local.example.php` в `config.local.php`, укажите свои DB_HOST, DB_NAME, DB_USER, DB_PASS. Файл с секретами исключён из Git.
4. Дайте PHP право записи в `storage/uploads`. Папку `storage` нельзя использовать для исполнения PHP. Для Apache ограничения включены в `.htaccess`; на Nginx добавьте правило запрета исполнения PHP внутри `/storage/` и запрет выдачи скрытых файлов, журналов и `config.local.php`.
5. Установите на сервере переменную `LMS_INSTALL_KEY` со своим случайным секретом. Откройте `/install.php`, введите этот ключ и создайте первого администратора. После создания аккаунта удалите `install.php` с хостинга и уберите ключ из окружения. При наличии пользователей установка закрывается.
6. Войдите в `/admin/`. В «Оформление и тексты» настройте свою платформу.
7. Создайте обучение, затем тест и/или практическое задание, привязанные к нему. Либо загрузите `examples/course.json` в «Импорт данных» как пример.
8. Добавьте пользователей или загрузите CSV по `examples/users.csv`, предварительно заменив все примеры и пароли. Назначьте обучения при создании/редактировании пользователя.
9. После прохождения проверьте ответы в «Результаты» и нажмите «Показать сотруднику результаты». В админке отображается статус доступности результата.

Самостоятельная регистрация отключена: аккаунты создаёт администратор. Для выдачи дополнительного времени на неотправленное практическое задание сохранён административный механизм повторного открытия ТЗ. Сотрудник сам не перезапускает тест.

## Почта и загрузки

Восстановление пароля использует PHP `mail()`. Настройте доставку почты и значения `MAIL_FROM_EMAIL` и `MAIL_FROM_NAME` в `config.local.php`; проверьте отправку письма перед запуском. Пока почта не настроена, администратор может изменить пароль через редактирование пользователя.

Для вложений до 300 МБ настройте `upload_max_filesize=300M`, `post_max_size=320M` и соответствующий лимит веб-сервера. Пользователь должен дождаться завершения загрузки и отправить ответ.

## Проверки

```sh
node tools/lms-regression.mjs
```

Проверяются очередность сохранения черновиков, повтор после потери соединения, блокировка истёкшей попытки, запись и повторная отправка ответа на ТЗ, принадлежность попытки, лимит размера, откат при ошибке, автосохранение выданных вопросов, фиксация ответов по окончании времени и UTF-8.

Эти проверки изолируют SQL тестовыми реализациями Database и не подтверждают работу на конкретном MySQL-хостинге. Также проверяется синтаксис PHP/JavaScript. Перед клиентским запуском нужны установка на тестовый MySQL, полный сценарий в браузере и проверка доставки почты/загрузок на целевом сервере.

## Поставка и GitHub

В репозиторий передаётся содержимое `lms-template`, без `config.local.php`, рабочих загрузок и журналов. PHP-приложение требует PHP/MySQL-хостинг: GitHub Pages его не выполняет. Старая HTML-демоверсия из упрощённой LMS не включается, поскольку не отражает эту версию.

Для резервной копии сохраняйте MySQL-дамп и `storage/uploads`. Бренд, обучающие материалы, вопросы и результаты хранятся в базе. Каждому заказчику нужна отдельная база и отдельная копия файлов.
